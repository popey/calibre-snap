## Migration regression and database observation

The native library and preferences had changed since the September 24 baseline.
Today's test preserved those changes: it backed up current state, restored it,
and verified all 41 library files and 8 preference files before copying the library.
The new backup, restoration, test copy and reports are under the ignored directory
`migration-test/retest-2026-09-25/`.

All 13 exported metadata records matched after path normalization; all 25 ebook
and cover checksums matched. Three SQLite integrity checks passed. A custom-column
edit in the snap copy did not change exported native metadata. Native calibredb
reopened the original successfully. Real supplied EPUB and PDF books converted
from the copy to nonempty text output.

All 12 supplied source files and 8 native preference files remained byte-identical
to their baselines. Of the 41 native library files, only metadata.db changed:
its SQL dump moved book 4's row from annotations_dirtied to metadata_dirtied.
Running native calibredb alone on a separate restoration reproduced exactly the
same SQL state. Thus the byte change is reproducible in the native reopen step;
no other SQL content changed. The pre-test backup retains the original bytes.
Do not interpret a native calibredb read as necessarily byte-preserving.

This repeats the established local regression coverage. It does not establish

install of this artifact. No Store upload or publication was performed.
